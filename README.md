# Лабораторная работа №5. Элементы сетевого программирования

## Вариант 4. Чат с временным хранением сообщений

- **Транспортный протокол:** TCP (Windows Sockets API / Winsock2).
- **Архитектура:** Один сервер (мультиплексирование через `select()`) и не менее трёх одновременно работающих клиентов (отдельные процессы).
- **Основные правила:**
  - Для отключённого пользователя сервер временно хранит до **20** непрочитанных сообщений в порядке поступления (FIFO).
  - При переполнении очереди (попытка отправить 21-е сообщение) новое сообщение отклоняется с кодом ошибки `QUEUE_FULL` и уведомлением отправителя.
  - После доставки накопленных сообщений по команде `GET_PENDING` клиент подтверждает получение (`ACK`), после чего сервер удаляет подтверждённые сообщения (исключается повторная выдача).

## Формат прикладного протокола

Каждое сообщение передаётся по TCP в следующем бинарном обрамлении:

`[Length: 4 байта (uint32_t, сетевой порядок байтов)][Payload: Length байт (UTF-8)]`

Максимальный размер полезной нагрузки: `65536` байт.

Структура `Payload`:

`VERSION|TYPE|REQ_ID|SENDER_ID|BODY`

- `VERSION` — версия протокола (`1`).
- `TYPE` — тип сообщения (`LOGIN`, `SEND`, `GET_PENDING`, `LOGOUT`, `ACK`, `OK`, `MSG`, `ERROR`).
- `REQ_ID` — целочисленный идентификатор запроса.
- `SENDER_ID` — целочисленный идентификатор участника (сервер использует `0`).
- `BODY` — полезная нагрузка, зависящая от типа сообщения.

### Таблица описания протокола

| Тип сообщения | Отправитель | Получатель | Содержимое (`BODY`) | Ожидаемая реакция |
| :--- | :--- | :--- | :--- | :--- |
| `LOGIN` | Client | Server | Пусто (идентификатор задаётся в `SENDER_ID`) | Авторизация клиента, возврат `OK` с числом ожидающих сообщений (`pending=N`) или `ERROR` |
| `SEND` | Client | Server | `<targetId>\|<text>` | Передача онлайн-адресату (`MSG`) либо сохранение в очередь (до 20). Возврат `OK` или `ERROR` (`QUEUE_FULL`) |
| `GET_PENDING` | Client | Server | Пусто | Отправка всех сохранённых сообщений в виде серии `MSG` по порядку FIFO и итогового `OK` (`count=N`) |
| `ACK` | Client | Server | `count=<N>` | Подтверждение получения очереди; сервер удаляет первые `N` подтверждённых сообщений и возвращает `OK` |
| `LOGOUT` | Client | Server | Пусто | Выход пользователя из сеанса, возврат `OK` и закрытие сессии |
| `MSG` | Server | Client | `<origSenderId>\|<seq>\|<text>` | Отображение полученного сообщения на клиенте |
| `OK` | Server | Client | Строка статуса (например, `pending=5`) | Подтверждение успешного выполнения команды |
| `ERROR` | Server | Client | `<errorCode>\|<description>` | Отображение ошибки на клиенте |
